## 1. THE WEEKLY FIT TEST — design, settled 2026-09-11, not yet built

The operator's standing Saturday job: **"are we trading as well as possible?"**
It went through three framings before landing. The final one is narrow and is
the one to build.

**NOT this:** what would a perfect day trading that symbol have looked like.
The hindsight optimum is computable and nearly useless — an upper bound nobody
could have taken, and tuning toward it fits noise.

**THE ACTUAL QUESTION, in the operator's words:** *"Based on the COA selected
by the plan, was it watching the 'right' indicators to inform its decision, and
were better ones available (in hindsight) at the time it decided."*

That is **feature attribution on a decision that already happened** — not entry
quality, not a backtest.

**Scope:** only plans that EXECUTED. No counting setups never taken.

**Design:**

- **Outcome = realized R, and it comes from `r_ledger`'s existing definition.**
  Do not restate it. If the study computes its own R, its ranking cannot be
  compared against the R ledger read every night — the same single-source rule
  as `price_bias` (dtp/standings.py) and `composite_call` (brief_bias_join).
- **The inputs the plan consulted are already recorded** — `plan_check` holds
  every rung, its value and pass/fail per tick; `plan_tick` holds the COA and
  the verdict. "What was it watching" is a READ, not a reconstruction.
- **The candidate pool is everything measurable at that timestamp**, not a
  curated list: the derived series (trend, vol, levels, sweep, gap, manifold
  sensors, the character axes now that r356 is live) plus the raw tape. A
  curated pool returns the author's prior with arithmetic attached.
- **The deliverable:** per executed plan — the COA, the rungs consulted with
  their values, the outcome, and a ranking of every available feature at that
  timestamp against that outcome, with the rungs actually used MARKED.
- **The interesting column is the RANK OF THE RUNGS THE PLAN WATCHED.** Near
  the top → the plan looks at the right things and the work is elsewhere.
  Mid-pack while something unused sits above them → that is the finding, and a
  bigger one than any threshold moved this week.

**Two rules that keep it honest:**

🔴 **LOOK-AHEAD IS GATED, NOT INTENDED.** Every candidate feature must be
computable from data stamped AT OR BEFORE the decision. A feature using a bar
that had not closed looks brilliant and is worthless. This must be a CHECK,
because the error is invisible in the output.

🔴 **FIX THE OUTCOME DEFINITION BEFORE RANKING.** Write down what a good
decision was, then rank. Adjusting the outcome after seeing which features win
is circular — the same error as re-deriving the character bands from
`character_ledger` instead of `character_axis_sample` (see CHR.1 / N5).

**Operator's framing, worth keeping:** *"this is less of a 'fitting' operation
and more of a 'pointing' one."* A pointer survives being wrong — one study
spent. A fit that is wrong costs live tape and money. So small n is tolerable
for GENERATING a candidate and never for acting on one; the disposition rule
(kill, keep, or codify) still applies.

- Repeated the panel's *"that is a dispatch gap"* as a finding without opening
  `authorize()` (PLN.1).
- `4.13 + 0.1` formatted to one decimal gives `4.2` — a version collision from
  float arithmetic on a version string. **Increment the minor as an int.**

🔑 **The pattern: reaching for an explanation before opening the file that
settles it.** Access removes the excuse, not the habit.

**What caught these, every time:** the lander (stale BASE, version with no
changelog entry, duplicate GENESIS row, a payload that would have reverted a
landed fix), a gate written earlier, or the operator reading his own code
faster. That is why §38.1 keeps the land checkpoint.

**A habit worth keeping:** run the lander's own BUMP rule locally before
cutting — title version equals newest dated changelog entry, and that entry
does not already exist at HEAD.

## 4. STATE AT HANDOFF — things a fresh instance would not infer

- **Claude Code is on control**: native install, `~/.local/bin/claude`, v2.1.268,
  Opus 5, **Claude Max subscription — NOT the API key.**
- ⚠️ `ANTHROPIC_API_KEY` IS in the interactive shell: `~/.bashrc` line 120 does
  `set -a; source ~/day_trader_pro/.env; set +a`. It is there for `selector.py`,
  which one devtools item runs in-shell (`orchestrator.py --dry-run --no-gate`).
  **Do not unset it globally** — launch Claude Code with
  `env -u ANTHROPIC_API_KEY claude` instead. Every timer already gets it via
  `EnvironmentFile=`, so the units never depended on the shell.
- ⚠️ **Do not launch from an active venv.** dtp and otv4 have different venvs and
  a session spans both repos; an ambient venv makes bare `python3` look correct
  while being the wrong interpreter. Name the interpreter per command, as the
  agreement already requires.
- `deactivate` restores the pre-venv PATH, which predates `~/.local/bin` being
  added — that is why `claude` vanished once.
- **Remote Control** (`/rc`) bridges a terminal session to the Claude app's
  **Code** tab. The session stays on the box; only messages and tool results
  cross. Known rough edges as of this writing: permission prompts may not render
  on mobile (plan-mode approvals can hang the phone while the terminal waits),
  idle sessions can drop while tmux stays alive, output arrives in chunks, and
  file sending is photos only — which is why `handoffs/` exists.
- **Do not run `/init`.** A generated CLAUDE.md would duplicate and possibly
  contradict the working agreement.

## 6. THE THREE TASK TYPES (agreed, not built)

- **Scheduled/recurring** — a systemd timer, never a menu item. `claude -p` with
  a fixed prompt file, `--allowedTools` read-only, `--output-format json` so
  every run is cost-accounted and reconstructable (§38.5 by construction).
- **Ad hoc studies** — a real interactive session. NOT menu items: the operator's
  r242 ruling stands, and no menu is needed now that there is no blob-through-
  Termius limit.
- **Audits** — the strongest fit for `-p`: walk a checklist, read-only, write the
  report to `reports/`, exit non-zero on a blocker so it composes with the
  conductor as another gate.

⚠️ A scheduled prompt has no human to clarify ambiguity mid-run. Scope each one
tightly — *"read X, report Y, change nothing"*, never *"check on the fleet."*
